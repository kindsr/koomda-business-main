# 표준 기능 분류 체계 (Taxonomy)

서비스마다 메뉴 이름과 구조가 다르기 때문에, 기능을 **서비스와 상관없는 표준 ID**에 연결해야 나중에 비교표를 만들 수 있습니다.

## 파일

| 파일 | 내용 | 사용 |
|---|---|---|
| `common.csv` | 모든 웹 SaaS에 공통으로 있는 기능 (인증, 권한, 알림, 검색, 관리자 등) | 항상 사용 |
| `preset-erp-groupware.csv` | ERP·그룹웨어 업무 기능 (메일, 결재, 근태, 인사, 급여 등) | `{{TAXONOMY_PRESET}}`로 지정 |

## 컬럼

| 컬럼 | 설명 | 예시 |
|---|---|---|
| `category_code` | 분류 코드 (영문 대문자 2~5자) | `APV` |
| `std_category` | 분류 이름 | `전자결재` |
| `std_feature_id` | 표준 기능 ID: `{category_code}-{3자리 번호}` | `APV-003` |
| `feature_name` | 표준 기능 이름 | `결재선 지정` |
| `description` | 기능 정의 (어떤 서비스에서든 같은 의미로 판단할 수 있게) | `결재자·합의자·참조자를 순서대로 지정` |

## 매핑 규칙

1. 분석한 기능이 표준 기능과 **같은 목적**이면 그 `std_feature_id`를 씁니다. 이름이 달라도 됩니다.
2. 하나의 화면 기능이 여러 표준 기능에 걸치면 **행을 나눠서** 각각 기록합니다.
3. 표준 목록에 없는 기능이면 `{category_code}-N{2자리 번호}` 형식으로 새 ID를 붙입니다. (예: `APV-N01`)
   - `feature-matrix.csv`의 `notes`에 `신규 후보`라고 적습니다.
   - 여러 서비스에서 반복해서 나오면 표준 목록에 정식 번호로 추가합니다.
4. 어느 분류에도 맞지 않으면 `ETC` 분류를 씁니다. (`ETC-N01`)

## 새 프리셋 추가하기

다른 유형의 서비스(CRM, 커머스 관리자, 프로젝트 관리 등)를 벤치마크할 때는 같은 컬럼으로 `preset-<유형>.csv`를 만듭니다.

- `category_code`가 `common.csv`나 기존 프리셋과 겹치지 않게 합니다.
- 처음에는 대분류와 핵심 기능 5~10개만 정의하고, 벤치마크를 하면서 `N` 번호로 나온 기능을 정식으로 추가합니다.
- 예시 코드: CRM 프리셋이면 `LEAD`(리드), `DEAL`(영업기회), `ACCT`(고객사), `QUOT`(견적) 등.
